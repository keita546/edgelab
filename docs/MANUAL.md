# エッジ検定ボード 説明書

過去の株価データで「ある売買ルールに、偶然では説明しにくい優位性があったか」を調べる道具です。
ダッシュボード（`site/dashboard.html`）にも同じ内容の説明書が入っています。

> 過去データの統計的検定であり、将来の成績や特定の売買を勧めるものではありません。

---

## 1. わかること・わからないこと

**わかること**：過去15年（日経平均は25年）の株価で、あるルールどおりに売買していたら、手数料を引いたあとも平均してプラスだったか。そしてそのプラスが「たくさん試したうちの偶然の当たり」で説明できてしまわないか。

**わからないこと**：そのルールがこれからも効くか。過去に効いていた規則性は、知られるほど、また相場の参加者が変わるほど消えていきます。

40通り試せば、まったく意味のないルールでも平均2つは「統計的に有意」に見えます。このツールはその見かけの当たりを落とすことに重点を置いています。

## 2. セットアップ

cd ~/Documents/GitHub/edgelab

## 3. よく使うコマンド

| やりたいこと | コマンド |
|---|---|
| ダッシュボードのデータを作り直す（既定6銘柄、数分） | `.venv/bin/python export.py` |
| 銘柄を指定して作り直す | `.venv/bin/python export.py 7203.T 6758.T 4063.T ^N225` |
| ダッシュボードの HTML を作る | `.venv/bin/python build_site.py` → `site/dashboard.html` |
| 1銘柄の検定結果を表で見る | `.venv/bin/python run.py --symbol 7203.T --intraday 5m --cost 10` |
| 資金シミュレーション | `.venv/bin/python sim.py 6758.T "RSI2<10→5日" --capital 3000000 --frac 50` |
| ツール自体の較正テスト（約3分） | `.venv/bin/python selftest.py` |

銘柄コード：日本株は末尾に `.T`（例 `7203.T`）、日経平均は `^N225`、米国株は `AAPL` など。

`site/dashboard.html` はブラウザで直接開けます（データはページに埋め込み済み）。

## 4. ダッシュボードの画面

| 画面 | できること |
|---|---|
| 結果 | 生き残り数のファネル、銘柄×ルールの色マップ、銘柄ごとの信頼区間・関門の合否・損益曲線 |
| シミュレーター | 初期資金・投入割合・コスト・複利/単利・100株単位・期間を決めて資産推移を再現。年別損益、モンテカルロ、取引履歴 |
| ルール辞典 | 各ルールの条件・入り・出口・狙いと、銘柄ごとの結果 |
| 説明書 | この文書と同じ内容 |

色マップの数字は、コスト控除後の1回あたり平均損益（bps）。国内の株価表示にならい、プラスを赤、マイナスを青で塗っています。◎は全関門通過、○は多重検定は通過したが最終関門で脱落。

## 5. 6つの関門

全部を通ったものだけが「全関門通過」です。

1. **コスト控除後の平均がプラス**：往復コスト（個別株0.10%、日経平均0.05%）を毎回引いても平均がプラスか。
2. **単独で見て有意（p < 0.05）**：保有期間の重なりを補正した Newey-West の t 検定。
3. **多重検定の補正後も有意（FDR 補正 p < 0.05）**：試した数を織り込む Benjamini–Hochberg 法。ほとんどのルールはここで消えます。
4. **シグナルが出ない日より良い**：入らなかった日に同じ向きで持った場合との Welch の t 検定。上昇相場に乗っていただけのルールを除きます。
5. **後半の検証期間でも同じ向き**：前半70%と後半30%で平均の符号が一致するか。
6. **試行回数で割り引いても残る（DSR > 0.95）**：Deflated Sharpe Ratio。試行数・分布のゆがみ・標本数で割り引いた「実力がゼロより大きい確率」。

### 判定ラベル

| ラベル | 意味 |
|---|---|
| 全関門通過（有望(要追試)） | 6つすべて合格。別期間・別銘柄での確認が必要な候補 |
| FDR通過・DSR不足 | 多重検定は越えたが、試行数で割り引くと 0.95 に届かない |
| IS/OOS不一致 | 前半プラス・後半マイナス。当てはめすぎの疑い |
| 補正で消滅 | 単独では有意だが、試した数を考えると偶然で説明できる |
| 優位性なし | 単独でも有意でない |
| 有意にマイナス | 補正後も確かに損をしている。逆向きでもコストは同じだけかかる |

## 6. シミュレーターの計算

`edgelab/simulate.py`（`sim.py`）とダッシュボードの JavaScript は同じ計算をします（ソニー・RSI2<10→5日保有・300万円・50%・10bps で両者が1円単位で一致することを確認済み）。

- ルールの売買を古い順に処理。同じ日の決済は新規より先。
- 1回の投入額 = 基準額 × 使う割合。基準額は複利なら「現金＋保有中の取得額」、単利なら初期資金。
- 現金が足りなければ手持ち現金まで。100株単位なら株数を切り捨て、0株なら見送り。
- 1回の損益 = 投入額 ×（騰落率 − 往復コスト）。騰落率は配当込み。
- 資産は決済時に更新。**保有中の含み損は反映しないので、実際の途中の落ち込みはもっと大きいことがある。**
- 空売りの担保・貸株料・規制、税金は考慮しない。
- 100株単位の必要資金は株式分割調整後の株価で計算するため、**過去ほど必要資金が小さく出る**。
- モンテカルロは実際の取引の損益率を無作為に引き直して1,000回積み上げる簡略計算（保有期間の重なり・100株単位は無視）。

**まず「このルール」と「持ち続けた場合」の最終資産を比べてください。** 統計的に有意なルールでも、相場にいる時間が短いので、持ち続けた方がはるかに増えることがよくあります（例：ソニーの RSI2<10→5日保有は +315%、持ち続けは +1333%）。

## 7. ダッシュボードの検索

- ルール名に加え、条件・入り・出口・狙いの説明文も対象。結果画面とルール辞典で共通。
- 空白区切りで AND 検索（`RSI 5日`、`窓 売り`）。全角半角・大文字小文字は区別しない。
- 判定（全関門通過・惜しい・有意にマイナスなど）と分類で絞り込める。
- `/` で検索欄へ、`Esc` で検索語を消す。

## 8. ルールを追加する

`edgelab/hypotheses.py` の `daily_hypotheses` に1行足します。例：「5日移動平均を上抜けた日の引けで買い、3日持つ」

```python
ma5 = d["close"].rolling(5).mean()
cross = (d["close"] > ma5) & (d["close"].shift(1) <= ma5.shift(1))
add(_mk("順張り:5日線上抜け→3日保有", "モメンタム", d, cross, +1, "c2c", 3))
```

`_mk(ルール名, 分類, データ, 条件, 向き(+1買い/-1売り), 損益の測り方, 保有日数)`。損益の測り方：

| 値 | 入り | 出口 |
|---|---|---|
| `c2c` | 引け | 保有日数後の引け |
| `o2c` | 寄り付き | 同日の引け |
| `c2o` | 引け | 翌日の寄り付き |

説明文は `edgelab/rules_doc.py` に足します。そのあと `export.py` → `build_site.py`。

**守ること**
- 条件には入る時点で分かっている情報だけを使う（翌日の値を使うと結果が良く見えすぎる）。
- シグナルと建値に同じ価格を使わない。寄り値で窓を判定して寄り値で入ると、寄り値のノイズだけで偽の優位性が出る（乱数データでも t = +15）。
- 追加したら `selftest.py` を流し、偽陽性率が約5%のままか確認する。
- ルールを足すと試行数が増え、ほかのルールの補正後 p 値も厳しくなる。

## 9. 用語集

| 用語 | 意味 |
|---|---|
| bps | 0.01%。10bps = 0.10% |
| 往復コスト | 買いと売り1往復の費用（手数料＋スプレッド＋約定のずれの見積もり） |
| 寄り付き / 引け | その日最初 / 最後の取引 |
| ザラ場 / オーバーナイト | 取引時間中 / 引けから翌日寄り付きまで |
| 窓（ギャップ） | 寄り付きが前日終値から飛んで始まること |
| RSI(2) | 直近2日の上げ下げの比率から作る0〜100の指標。10未満は急に売られた状態 |
| p 値 | 本当は優位性ゼロなのに偶然この結果が出る確率 |
| FDR | 合格としたものに偶然の当たりが混じる割合。5%以下に抑えるよう p 値を補正 |
| DSR | 試行数などで割り引いたシャープレシオが本当にプラスである確率 |
| IS / OOS | ルールの良し悪しを見た前半 / 検証用に取っておいた後半 |
| 95% 信頼区間 | 本当の平均がおそらく入る範囲（定常ブートストラップ） |
| 検出力 | 5bps の優位性が本当にあるとき、有意と判定できる確率 |
| プロフィットファクター | 利益合計 ÷ 損失合計 |
| 最大ドローダウン | 資産が途中の最高値から最も減った割合 |
| CAGR | 毎年同じ率で増えたとみなした1年あたりの率 |
| 単元株 | 日本株の売買単位（原則100株） |

## 10. 限界と注意

- 同じルールが複数銘柄で効いて見えても独立した確認ではない（RSI(2)<10 は同じ急落日に一斉に点灯する）。
- 5分足は無料データの制約で直近約60日。5分足の「優位性なし」は「判断できない」。
- 売買による価格への影響、空売りの制約、税金は未考慮。
- 現在上場中の銘柄のみ（生存者バイアス）。
- データは Yahoo Finance の無料データ（yfinance）。誤りや欠損がありうる。
